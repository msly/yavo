# Yavo 所有权与资源语义表（草案 v0.3）

这是 P1 开工前要冻结的规范：编译器按这里实现，速查卡从这里提炼。每条规则有编号，第 9 节的测试集给每条规则至少配一个应通过和一个应拒绝的程序。状态：草案，没有经过编译器实现验证；代码中的反例是待加入的验收测试，不是已经复现的编译器漏洞。

## 1. 访问权限

- **A1 绑定可变性与借用权限分开。** `let`/`var` 只决定绑定能否重新赋值；`&T`/`&inout T` 决定能否修改目标。把 `&T` 放进 `var` 不能获得写权限；`let` 绑定可以持有 `&inout T` 并通过它修改目标，但不能换成另一个引用。
- **A2 模式绑定继承访问路径已有的权限。** `if let`、`for`、`match` 的绑定，来自可变路径（`var` 拥有的值、`inout` 参数、`&inout T`）时可写，来自只读路径（`let` 拥有的值、普通参数、`&T`）时只读。任何绑定都不能把只读借用升级成可变借用。
- **A3 排他性。** 同一个位置在同一时刻，要么有任意多个只读借用，要么只有一个可变借用。禁止的是冲突访问，不是禁止通过可变借用本身修改目标。
- **A4 再借用。** 可以从 `&inout T` 再借出它的子字段或整体，例如 `insert(&n.left, k)`。再借用存活期间，原路径不能做冲突访问；再借用结束后，原借用恢复可用。
- **A5 Map 的键只读。** 遍历或 `getMut` 得到的键永远是 `&K`；要改键，先删除再重新插入。

## 2. 复制、移动与读取

| 类型 | 赋值或传参时 | 说明 |
| --- | --- | --- |
| 标量（整数、浮点、`bool`、`byte`）、`Id[T]` | 复制 |  |
| `str`、`&T`、只读 `[]T` | 复制描述符 | 不复制被引用的数据；副本携带同样的来源 |
| `&inout T`、可变 `[]T` | 不可复制 | 只能移动或受检查地再借用 |
| `String`、`Vec[T]`、`Map[K, V]`、`Box[T]` 等拥有值 | 移动 | 要第二份写 `.clone()` |
| 携带借用的拥有值，如 `Vec[str]` | 移动 | 容器拥有自己的存储，元素借用外部数据；借用关系随容器移动 |
| 字段全部是标量的结构体、元组、枚举 | 复制 | 编译器自动判断，不需要声明 |

- **C1 携带借用。** 一个类型直接或递归地包含 `str`、`&T`、`&inout T` 或 `[]T` 时，就“携带借用”。携带借用的值服从第 4 节的逃逸限制，即使它自己拥有存储。销毁它只释放它自己的存储，不释放被引用的数据。
- **C2 `v[i]` 的含义。** 在读取上下文中：元素可复制时得到副本（`str` 元素得到描述符副本，指向原字符串，而不是容器的槽位）；元素不可复制时得到 `&T`，同时借用容器。在赋值左侧或 `&v[i]` 中得到可变位置，要求可变访问路径。
- **C3 `.toVec()` 与 `.toString()`。** `.toVec()` 只让容器拥有元素存储，元素是否携带借用取决于元素类型：`[]str` 得到的 `Vec[str]` 仍然携带借用；要完全独立，逐个转成 `Vec[String]`。`.toString()` 得到不携带借用的 `String`。
- **C4 读取可复制的值。** 期望类型是可复制的 `T`、实际是 `&T` 时，编译器自动读取一次（第 8 节白名单）。所以 `for k, n in counts` 中 `n` 是 `&int`，`items.push((k.clone(), n))` 合法。

## 3. 借用来源（`of`）与写入关系

- **O1 所有具名函数和方法都写来源。** 包括私有函数和接口方法；返回值携带借用时（含 `Vec[str]`、可选值、元组、结果类型里的借用），签名必须写 `of`。纯拥有值的返回不写。

```
fn trimmed(text: str) -> str of text
fn choose(a: str, b: str, pickA: bool) -> str of (a, b)
fn name(self) -> str of self
fn languageName() -> str of static
fn words(text: str) -> Vec[str] of text
```

| 写法 | 含义 |
| --- | --- |
| `of text` | 来自参数 `text` |
| `of self` | 来自接收者 |
| `of (a, b)` | 可能来自其中一个或多个；调用方按全部列出的来源保守检查 |
| `of static` | 只指向程序全程有效的数据，例如字符串字面量、`os.args()` |

- **O2 来源是上界。** 编译器检查函数体没有超出声明；调用方只看签名，不读函数体去缩小或扩大来源。实现改了而违反声明时，错误报在函数内部，不会传到调用方。
- **O3 不自动补 `of`。** 缺失或写错时，编译器给出候选补丁，但不自动应用，也不自动扩大已声明的来源。
- **O4 不能通过参数写入新借用。** v1 中，普通函数不能把来自其他输入的借用写进调用者传入的 `inout` 参数（视图容器、可选值、嵌套集合都算）；需要时改为返回带 `of` 的结果。函数内部的局部容器不受限制。内建集合操作按编译器的固定契约传播来源：`out.push(s)` 之后，`out` 借用 `s` 的来源。
- **O5 闭包。** 不逃逸的匿名闭包（立即传给 `sortBy`、`update` 等）可以借用外部变量，来源在当前函数内推断。会被保存的闭包（如 `Heap.by` 的比较函数、放进字段的闭包）不能捕获任何借用，只能移动捕获拥有值。

## 4. 逃逸限制

- **E1 能去哪里。** 携带借用的值可以做局部变量、参数和带 `of` 的返回值；不能进入普通字段、`Box`、`Rc`、`Arc`、接口值、channel、全局变量或会被保存的闭包。
- **E2 递归检查。** 包在泛型结构、可选值、元组、结果类型或其他容器里同样受限：`Box[Vec[str]]`、`Wrapper[str]`、类型为 `?&T` 的字段都会被拒绝。
- **E3 证明不了就拒绝。** v1 宁可误拒：编译器无法证明不逃逸的组合一律拒绝，诊断说明原因，并给出改用拥有值的写法。
- **E4 赋给外层变量。** 把携带借用的值赋给外层作用域的变量时，来源必须活得至少和那个变量一样久。
- **E5 长期保存的办法。** `.toString()`、逐元素转成 `String`，或者只存下标区间。

## 5. 并发与资源

编译器从类型结构自动推导两种能力：`Send`（拥有值可以交给另一个线程）和 `Sync`（`&T` 可以被多个线程同时使用）。v1 不允许手写这两种能力。

| 操作 | 条件 |
| --- | --- |
| 把拥有值 `T` 交给另一个线程（`spawn` 的移动参数、channel 发送） | `T: Send` |
| 多个线程共享只读借用 `&T` | `T: Sync` |
| `Arc[T]` 跨线程 | `T: Send` 且 `T: Sync` |
| `Arc[Mutex[T]]` 跨线程 | `T: Send` |
| `Rc[T]` | 永远不能跨线程 |

- **P1 `Arc[Mutex[Rc[T]]]` 必须拒绝。** 锁只保护它里面那一份值，保护不了 `Rc` 在别处的别名；这个类型也不能作为任何诊断的自动修复结果。
- **P2 接口值的能力。** `Box[Named]` 擦除了具体类型，默认既不是 `Send` 也不是 `Sync`；需要跨线程时写 `Box[Named + Send]`，装箱时检查具体类型。
- **P3 线程借用持续到线程确认结束。** `scope` 里 `spawn` 借用的数据，借用一直持续到 `scope` 等待所有线程结束，而不是到线程句柄最后一次被使用。`return`、`try`、`break` 提前离开 `scope` 时，先等待所有线程结束，再释放数据；丢弃句柄不解除借用；线程不能借用比 `scope` 更短命的局部变量；线程的返回值不能借用线程自己的局部数据。
- **P4 锁守卫。** `with g = m.lock() { }` 里从 `g` 借出的引用只能在块内使用：离开块后，即使 `m` 还活着，访问也不再受锁保护。借用系统同时跟踪两种存活：数据的存活，以及访问许可（锁守卫）的存活。
- **P5 channel 契约（v1）。** 元素类型必须是 `Send` 且不携带借用；`send` 移动值；关闭后 `send` 返回 `err(.Closed(value))`，把值还给调用者；关闭后 `recv` 先排空缓冲区，再返回 `none`。

## 6. 求值顺序、析构和丢弃

- **V1 调用的求值顺序。** 先处理被调用对象或方法接收者，再从左到右处理实参；每个实参求值完成后，立即完成复制、移动或借用，再处理下一个。
- **V2 不做两阶段借用。** `v.push(v.len())` 被拒绝（接收者已被可变借用）；`consume(v, v.len())` 被拒绝（`v` 已移动）。规范写法是先拆出临时变量 `let n = v.len()`。这种拆分不改变语义，`yavo fix` 可以自动应用。
- **V3 提前退出。** 后面的实参通过 `try` 提前返回时，已经构造的拥有临时值照常清理，已经发生的移动不会撤销。
- **V4 析构顺序。** 局部变量在作用域结束时按声明的逆序析构，正常结束、`return`、`try`、`break` 都一样；临时值在所在语句结束时析构；被移走的值不析构。借用结束不等于析构拥有者。
- **V5 覆盖赋值。** `x = 新值` 先求出新值，再析构旧值，然后写入。
- **V6 部分初始化。** 结构体字面量的字段按书写顺序求值；中途失败时，已求出的字段按逆序析构。
- **V7 `_` 与 `_name`。** `let _ = f()` 立即丢弃结果，文件、锁马上释放；`let _name = f()` 保留到作用域结束，只是不触发“未使用”警告。`yavo fix` 处理未使用的变量时改名为 `_name`，不改变对象寿命。
- **V8 `return` 和分支取值。** 有返回值的具名函数、方法和块体闭包，每条能正常结束的路径都必须写 `return`；没有返回值的函数可以自然结束；永不返回的路径（`panic`、`os.exit`）不需要 `return`。`return` 总是从当前函数或闭包返回，不给分支提供值。需要分支取值时用表达式形式：单表达式闭包 `(a, b) => a < b`、`match` 的 `=> 表达式` 分支、`f() catch e => 替代值`；块形式的 `catch e { }` 必须离开（`return`、`break`、`continue`、`panic`）。
- **V9 `??` 短路。** 只有左侧是 `none` 时才计算右侧。

## 7. 数值、字符串与内存

| 情况 | 行为 |
| --- | --- |
| 加、减、乘、取负溢出 | panic；生成的 C 用 `__builtin_*_overflow` 检查 |
| 除以 0、对 0 取余 | panic |
| 最小整数除以 -1，或对 -1 取余 | panic |
| 移位量为负，或不小于位宽 | panic |
| 窄化转换超出范围，如 `i32(x)` | panic；需要截断时写 `i32.wrap(x)` |
| 负数转无符号 | panic；需要截断时写 `u32.wrap(x)` |
| 浮点转整数 | 向零截断；NaN、无穷或超出范围时 panic |
| 浮点运算 | 按 IEEE 754，不 panic；`NaN != NaN` |
| `+%`、`-%`、`*%` | 按位宽回绕 |

`-fwrapv` 只是有符号加、减、乘的回绕兜底，不实现上面的 panic，也不覆盖除法、移位和转换；每种运算都有独立的生成规则和边界测试。

- **S1** `String` 和 `str` 始终是合法的 UTF-8。
- **S2** `s.len()` 和 `s[i]` 按字节计算，`s[i]` 返回 `byte`。
- **S3** `s[a..b]` 的两端必须落在字符边界上，否则 panic。
- **S4** 任意字节先放进 `Vec[byte]`，再用 `String.fromUtf8(bytes)` 验证，得到 `String ! Utf8Error`；没有 `pushByte`。
- **M1 内存耗尽** 时终止进程，和 panic 一样不展开栈。
- **M2 容量计算溢出**（元素个数乘以元素大小等）时 panic，不会分配出过小的缓冲区。
- **M3 分配契约。** 标准库每个操作标注“不分配”或“可能分配”。`yavo allocations` 对一个函数给出三种结果：已知不分配、可能分配、未知（接口调用、C 函数、未知闭包）。参数求值单独计算：`println("${makeString()}")` 里 `println` 不分配，但 `makeString()` 可能分配。
- **M4 集合字面量。** `[1, 2, 3]`、`[:]` 是显式的分配构造；除此之外，普通语法不引入堆分配。
- **M5 `os.args()`** 在进程启动时解析一次（Windows 上这一步会分配），之后返回 `[]str of static`，调用本身不分配。

## 8. 隐式操作白名单与比较协议

v1 只有下面这些自动操作，其余一律要显式写出；这和“没有隐式转换”并不矛盾，因为白名单是封闭的。

| 自动操作 | 例子 |
| --- | --- |
| 在返回 `T ! E` 的函数里返回 `T`，自动包装为成功值 | `return n` |
| `T` 用在需要 `?T` 的地方，自动包装为有值 | `t = Box(Node{key: k})`、`return best` |
| 需要可复制的 `T`、实际是 `&T` 时，自动读取一次 | `items.push((k.clone(), n))` |
| 方法调用时自动借用接收者 | `v.len()`、`s.trim()` |
| 拥有值传给只读参数时自动借用 | 把 `String` 传给 `str` 参数 |
| 装箱的具体类型用在需要接口的地方 | `Box(Dog{})` 当作 `Box[Named]` |

- **K1** `==`、`!=` 只用于实现了内建 `Eq` 协议的类型；`<`、`>`、`<=`、`>=` 只用于实现了 `Ord` 的类型。数字、`bool`、`byte`、`str`、`String`（按字节比较），以及元素都可比较的元组自动实现。
- **K2** 用户类型要比较时显式声明，例如 `struct Version: Ord`，并实现 `fn cmp(self, other: &Version) -> Ordering`。这是唯一的比较协议，不是一般的运算符重载。
- **K3** 闭包捕获的规则见 O5。

# 新语言规划：面向 agent 的无 GC 系统语言

Nov 10, 2026 · @ali tea

## 定位与目标

这门语言是面向 agent 写代码的“带所有权检查的 C 替代品”：无 GC，性能接近 C，交叉编译方便，项目目录不留中间产物。

硬性要求有四条：

1. 无 GC。
2. 性能接近 C。
3. 跨平台编译方便，第一天就包含 Windows。
4. 使用者是 agent：代码由 AI 生成，人只写规格和看结果。

由第 4 条推出的设计原则：

- **迭代轮数比打字成本重要。** 样板代码可以多，歧义不能多。
- **没人读代码，正确性靠机器验证。** 测试、契约、审计要内置。
- **没有训练数据。** 模型只能靠一页速查卡和编译器的反馈来学。
- **检查只看单个函数和签名。** 改一处不会在远处引发错误。
- **零隐藏行为。** 没有隐式分配、隐式拷贝、隐式控制流。

## 依据

本规划是有依据的假设，不是定论：数据来自一个 agent、10 道 30 到 150 行的小题，在一台 Linux x86-64 沙箱里测得。

| 测量项 | Gojo（nightly 0.0.1-20261109） | Rust 1.75 |
| --- | --- | --- |
| 10 道题最终通过 | 10/10 | 10/10 |
| 一次通过 | 7/10 | 10/10 |
| 总尝试次数 | 14 | 10 |
| 编译通过后测试失败 | 0 次 | 0 次 |
| 编译耗时中位数 | 109 ms | 260 ms（波动大） |
| 二进制，strip 后中位数 | 约 200 KB | 约 390 到 430 KB |
| 项目目录内的中间产物 | 无 | cargo 零依赖时 13 到 16 MB |
| 带一个 regex 依赖时的产物 | 缓存多一个二进制大小的文件 | `target/` 50 到 104 MB |
| 工具链体积 | 编译器 4.7 MB | 约 294 MB |

Gojo 的 4 次失败全是编译失败：3 次来自所有权和视图模型，1 次来自“未使用变量即报错”。

关于这些数字的三点说明：

- Rust 是 apt 打包的版本，标准库自带调试信息，未 strip 的二进制有 13 MB，所以只比较 strip 后的大小。
- 每题先写 Gojo 后写 Rust，Rust 的一次通过率因此偏高；写题的 agent 对 Rust 和 Go 也有很强的先验。
- token 消耗没有测到，性能没有比较。

Windows 移植的测量：Gojo 生成的 C 可直接为 Windows 编译（0 个错误），但运行时拼成一个单元后有 464 个错误、15 个缺失头文件，集中在调度器、网络、子进程和内存映射。

## 取舍

只拿 Gojo 被实测验证过的优点，把它的短板从设计上避开。

| 做法 | 决定 | 理由 |
| --- | --- | --- |
| 无生命周期标注、单函数可检查的所有权模型 | 借鉴 | 小题上没有把 agent 卡死，错误集中在少数几类 |
| `?T` 取消 nil，`T ! E` 加 `try`/`catch` | 借鉴 | 编译通过的程序全部一次通过测试 |
| 编译成 C，生成代码只依赖一个小头文件 | 借鉴 | 生成的 C 可直接为 Windows 编译 |
| 编译约 100 ms、二进制约 200 KB、项目零产物、缓存有上限 | 借鉴 | 实测数据，缓存保留最近 64 个二进制 |
| 内置测试、种子可重放、`unsafe` 审计、从类型推导能否跨线程 | 借鉴 | 没人读代码时，这些是主要防线 |
| M:N 调度器、手写汇编、epoll | 不要 | Windows 移植的 464 个错误主要来自这里 |
| 借用持续到词法块结束 | 改 | T04 因此多花一次迭代，改为到最后一次使用为止 |
| 提示用 `.clone()` 修“移出 Box 字段” | 改 | 合法但会深拷贝，应直接建议 `take` |
| 未使用变量是编译错误 | 改 | 浪费一次编译往返，降为警告并可自动修复 |
| HTTP、TLS、YAML 进标准库核心 | 不要 | 推高实现和移植成本，放到包里 |
| 仓库没有许可证文件 | 避开 | 新语言从第一天就写明开源许可证 |

## 语言设计

语法贴近 Rust 和 Go 的混合，让模型已有的知识能迁移；具体写法见“速查卡”标签页。

**语法**

- 一件事只有一种写法，官方格式化工具只有一种风格。
- 没有宏、运算符重载、隐式转换。
- 声明顺序无关，不需要前向声明或头文件。
- 函数边界写显式类型，函数内可以推导。

**类型**

- 结构体、带数据的枚举、接口、元组。
- 泛型用单态化实现，可以用接口约束。
- `?T` 表示可能缺失，`T ! E` 表示可能失败，错误必须处理。

**内存模型**

- 值默认 move；参数有三种模式：借用（默认）、`inout`（可变借用，调用处写 `&`）、`sink`（移入）。
- 视图（`str`、`[]T`）只能放在局部变量和参数里，不能进字段和集合。
- 借用持续到最后一次使用为止，不是到词法块结束。
- `take`、`replace`、`swap` 是内建操作，诊断在需要时直接推荐。
- 堆上的值用 `Box`，共享用 `Rc` 和 `Arc`，图和树用 `Arena[T]` 加带代数的 `Id[T]`。
- 所有检查只看单个函数体和被调函数的签名，没有生命周期标注。

**安全**

- 没有未定义行为。
- 整数溢出和越界默认 panic；需要回绕时写 `+%`、`-%`、`*%`。
- `unsafe` 块可以被工具列出，依赖里默认禁止。

**并发（v1）**

- 只有 OS 线程、`scope`、channel、`Mutex` 和原子类型，I/O 是阻塞式的。
- 一个类型能否跨线程由编译器从它的结构推导。
- 不做协程和 M:N 调度器，这是为了保持运行时小而且可移植。

## 工具链和运行时

编译器先生成 C，运行时分成“可移植核心”和“平台层”两层，三个桌面平台从第一天就一起支持。

&#91;embedded content: 编译流程和两层运行时 · 三套平台实现\]

读图：前端的检查结果以 JSON 返回给 agent；生成的 C 只和运行时打交道，换平台只需要换平台层的实现。

**运行时分两层**

- 可移植核心：字符串、容器、Unicode、panic 和各种检查，不包含任何系统头文件。
- 平台层：约 30 个函数的小接口，覆盖内存、文件、时间、随机数、线程、进程；分 POSIX、Win32、WASI 三套实现。
- 生成的 C 只包含一个运行时头文件。

**目标平台**

- 第一阶段：Linux（x86-64、aarch64，musl 静态链接）、macOS、Windows。
- 第二阶段：wasm32-wasi。
- 本机编译用系统的 C 编译器；交叉编译走 `zig cc`，命令是 `build --target <目标>`。

**后端**

- 先生成 C，并输出 `#line` 指令，让报错能定位到源码行。
- 之后再考虑不依赖 C 编译器的直接后端（QBE 或 Cranelift）。

**产物和缓存**

- 编译器是单个可执行文件，运行时预编译一次，所有项目共享。
- 项目目录里不产生中间文件；全局缓存按内容寻址，有大小上限，按最近使用淘汰。
- 调试信息默认分离，不做增量编译（编译本身要足够快）。
- 依赖用锁文件固定，构建不联网、不执行构建脚本；依赖编译一次进共享缓存。

**编译器实现语言**

倾向用 Rust 且不引第三方依赖：强类型对 agent 写编译器有帮助，分发也是单文件。这一条可以改成 Go。

## 给 agent 的接口

编译器是 agent 的眼睛：每多一轮“编译、报错、修改”都是成本，所以诊断和查询要为机器设计。

**诊断**

- 输出 JSON：稳定的错误码、精确的位置、可机器应用的修复补丁。
- 修法要地道，不只是合法：移出 `Box` 或可选字段时建议 `take`，不是 `.clone()`。
- 借用类错误同时指出借用开始的位置和冲突的位置。
- 一次报全，不产生级联的假错误。
- lint（未使用的变量、导入）默认是警告，`fix` 命令自动修复；CI 模式再升级为错误。

**查询命令**

| 命令 | 作用 |
| --- | --- |
| `check` | 只做类型和所有权检查，不生成代码 |
| `outline <包>` | 只输出签名，agent 不必读整份源码 |
| `type-at <文件:行:列>` | 显示推导出的类型 |
| `explain <错误码>` | 短说明加一个错误写法和一个正确写法 |
| `doc <模块>` | 标准库文档，Markdown 输出 |
| `fix` | 应用诊断里的修复补丁 |
| `audit` | 列出 `unsafe`、`unwrap`、关闭检查的位置 |

**速查卡**

一页规范，能整份放进模型的上下文；标准库最常用的入口（读输入、集合、排序、字符串）都写在里面。试点中 Gojo 查了约 6 轮文档，速查卡要把这类检索降到接近零。

## v1 范围与非目标

v1 只做满足四条硬性要求所必需的东西，其余推到第二阶段或交给包。

| 项目 | v1 | 说明 |
| --- | --- | --- |
| 所有权和借用检查 | 做 | 核心卖点 |
| C 后端，Linux、macOS、Windows | 做 | 硬性要求 |
| 小标准库：io、fs、os、集合、字符串、时间、线程、测试 | 做 | 够写命令行工具和计算程序 |
| JSON 诊断和查询命令 | 做 | agent 的主要接口 |
| 内置测试、`audit` | 做 | 没人读代码时的防线 |
| 契约（`requires`/`ensures`） | 第二阶段 | 先做运行时检查，静态证明更晚 |
| 能力系统（包声明能碰哪些资源） | 第二阶段 | 先做包级声明，不做效应推断 |
| wasm、直接后端 | 第二阶段 | 不影响前三条要求 |
| 编译期执行（comptime） | 不做 | 实现成本高，编译期错误对 agent 更难诊断 |
| async 和协程 | 不做 | 会让运行时变重、移植变难 |
| 把引用存进结构体 | 不做 | 多一套规则，就多一套没有训练数据的东西 |
| 包注册表 | 不做 | 先支持本地路径和 git 依赖 |
| 内建 HTTP、TLS | 不做 | 交给包 |

## 路线图与验收线

路线图按验收标准排，不按日期排；每一步都用已有的实验框架（10 道题、统一的编译和测试脚本）来验收。

1. **速查卡、语法解析器、格式化工具。** 验收：agent 只凭速查卡写出 T01 到 T10，全部能解析。
2. **类型检查和 move 检查，加 JSON 诊断。** 验收：10 道题通过 `check`，每个错误都带可应用的修复。
3. **C 后端、核心运行时、三套平台层。** 验收：T01 到 T10 在 Linux、macOS、Windows 上全部通过。
4. **借用检查，加对抗测试集。** 验收：一组“试图绕过检查”的程序全部被拒绝，10 道题仍然通过。
5. **小标准库和查询命令。** 验收：10 道题不需要查速查卡以外的文档。
6. **agent 评测。** 扩到 30 道题（含 300 行以上、多文件的），多个模型各跑一遍，记录真实 token。

**验收线**（取自试点的基线）

| 指标 | 目标 | 基线来源 |
| --- | --- | --- |
| T01 到 T10 一次通过 | 不低于 7/10 | Gojo 试点 |
| T01 到 T10 总尝试次数 | 不高于 14 | Gojo 试点 |
| 小程序编译耗时 | 200 ms 以内 | Gojo 中位数 109 ms |
| 二进制，strip 后 | 不超过 250 KB | Gojo 约 200 KB |
| 项目目录内的中间产物 | 0 | Gojo |
| Windows 交叉编译 | 10 道题全部通过 | Gojo 目前不支持 |

第 6 步的数据如果不比“Rust 加工具层”好，就要重新考虑是否继续。

## 主要风险与待验证假设

最大的风险是冷启动：新语言没有训练数据，要到路线图第 1 步才能验证速查卡是否够用。

| 风险或假设 | 为什么是问题 | 怎么验证 |
| --- | --- | --- |
| 冷启动 | 模型对新语法没有先验，试点里 Gojo 的语法接近 Rust 和 Go，迁移几乎免费 | 第 1 步：只给速查卡，看能否写出并解析 10 道题 |
| 借用检查的可靠性 | 没有生命周期标注的检查容易漏判，Gojo 为此写了 151 个对抗程序 | 第 4 步：自建对抗测试集，加模糊测试 |
| 证据偏薄 | 一个 agent、10 道小题，所有权的压力通常出现在更大的程序里 | 第 6 步：30 道题、多个模型、随机化顺序 |
| 视图不能存进数据结构 | T10 里只能让每个 token 持有自己的字符串，多了堆分配 | 第 6 步里加零拷贝解析类的题，量化运行时代价 |
| 差异化不足 | 结构化诊断、契约、审计也能做成 Rust 之上的工具层 | 第 6 步与“Rust 加工具层”对比迭代次数和 token |
| 范围蔓延 | 调度器、网络协议、注册表都会拖慢核心 | 严格按“v1 范围与非目标”一节执行 |

还没有回答的问题：

- 语言叫什么名字，用什么开源许可证？
- 编译器用 Rust 还是 Go 写？
- 交叉编译是要求用户自己装 zig，还是随编译器一起分发？

### 析构

```text
struct Resource: Drop {
    label: String
    fn drop(inout self) {
        println("close ${self.label}")
    }
}
```

只能编译器调用 `drop`，不能手动 `.drop()`；要提前释放已有拥有值，写 `let _ = resource`。完整对象先执行用户 drop，再按字段声明逆序清理；未完成构造不执行整体 drop。带析构的类型不是 Copy。普通退出有清理，panic 和 os.exit 不展开栈。

## 6. 求值顺序、析构和丢弃

- **V1 调用的求值顺序。** 先处理被调用对象或方法接收者，再从左到右处理实参；每个实参求值完成后，立即完成复制、移动或借用，再处理下一个。
- **V2 接收者两阶段借用（2026-11-21 修订，原为“不做两阶段借用”）。** 修改接收者的调用（接收者是变量或其字段；接收者本身是返回 `&inout` 的调用时不适用，如 `pick(&v).push(v.len())` 仍被拒绝）（`v.push(x)`、`m.set(k, v)`、`s.add(x)`、`d.pushBack(x)`、`a.add(x)`、`inout self` 方法）以及下标赋值 `v[i] = x` 中，接收者在实参求值期间只被**预留**：实参可以读取它（`v.push(v.len())`、`v.push(v[i] + v[j])`、`c.add(c.n)`、`v[v.len() - 1] = x`），但不能修改、移动或可变借用它（`E0403`），实参的值也不能在调用开始后仍指向它（如 `t.push(t)`、`v.push(v[0])` 中保留的借用，`E0403`）；全部实参求值后接收者才取得排他访问。非接收者位置不变：`consume(v, v.len())` 仍被拒绝（`v` 已移动）。`yavo fix` 只对编译器已证明安全的固定模式自动拆分：接收者是稳定的局部位置，被提前计算的是已知无副作用的读取，例如把 `v.push(v.len())` 改成 `let n = v.len()` 再 `v.push(n)`。拆分不得改变副作用顺序、条件执行关系或资源清理时点，也不得重复调用接收者；其他情况只给候选补丁。
- **V2a 元素作接收者（2026-11-22）。** 接收者是经过下标的位置（`v[i]`、`v[i].f`、`g[r][c]`）且方法修改接收者时，先按 C2 定位元素（求下标、越界检查）并取得对该元素的可变借用，再从左到右求实参；元素借用记在容器上，所以实参不能使用该容器（读也不行，`E0403`）。只读方法照常求值，不借用容器。
- **V3 提前退出。** 后面的实参通过 `try` 提前返回时，已经构造的拥有临时值照常清理，已经发生的移动不会撤销。
- **V4 析构顺序。** 局部变量在作用域结束时按声明的逆序析构，正常结束、`return`、`try`、`break` 都一样；临时值在所在语句结束时析构；被移走的值不析构。借用结束不等于析构拥有者。
- **V5 覆盖赋值。** `x = 新值` 先求出新值，再析构旧值，然后写入。下标赋值 `v[i] = x`（C2）同样先求新值，再求下标并检查越界，再析构旧元素、写入；`v[i] op= x` 先求右侧，再读写元素。
- **V6 部分初始化。** 结构体字面量的字段按书写顺序求值；中途失败时，已求出的字段按逆序析构。
- **V6a 字段默认值（2026-11-21 新增）。** 结构体字段可写常量默认值 `field: T = value`，`value` 限数值、`true`/`false`、字节、无插值的字符串字面量（用于 `String` 字段）、`none`、`[]`、`[:]`，其他写法或类型不符是编译错误。字面量省略该字段时，每次构造都重新得到这个值，在书写的字段之后求出（常量没有可观察的求值顺序）。可选字段没有写默认值时省略即为 `none`。
- **V7 `_` 与 `_name`。** `let _ = f()` 立即丢弃结果，文件、锁马上释放；`let _name = f()` 保留到作用域结束，只是不触发“未使用”警告。`yavo fix` 处理未使用的变量时改名为 `_name`，不改变对象寿命。
- **V8 `return` 和分支取值。** 有返回值的具名函数、方法和块体闭包，每条能正常结束的路径都必须写 `return`；没有返回值的函数可以自然结束；永不返回的路径（`panic`、`os.exit`）不需要 `return`。`return` 总是从当前函数或闭包返回，不给分支提供值。需要分支取值时用表达式形式：单表达式闭包 `(a, b) => a < b`、`match` 的 `=> 表达式` 分支、`f() catch e => 替代值`。块形式的 `catch e { }` 不能正常走到结束的花括号；这一点按控制流判断，而不是看块里有没有出现 `return` 等关键字。
- **V9 `??` 短路。** 只有左侧是 `none` 时才计算右侧。

- **V10 用户析构。** 使用 `struct T: Drop { fn drop(inout self) { ... } }`。仅编译器可以调用这个方法；用户不能显式调用 `.drop()`。它返回 `()`，不能声明 `! E`，失败须在方法内处理或 panic。正常释放时先调用本体 drop，再按字段声明逆序自动析构字段；完整元组按位置逆序、容器按元素索引/插入顺序逆序，枚举只析构当前有效载荷。部分初始化失败只析构已完成字段（逆完成顺序），不调用未完成整体的用户 drop。
- **V11 析构安全边界。** 有 Drop 或含需析构资源的类型不自动 Copy；移动转移唯一析构责任，`clone` 必须显式提供有效语义。析构体不得把 `self` 整体移动、`take`、覆盖或替换，也不得让其借用逃逸；可以通过 `take/replace` 操作有完整替代值的字段。panic、内存耗尽和 `os.exit` 终止进程，不执行栈展开；普通错误返回执行正常清理。借用活跃时不能析构拥有者。
- **V12 错误绑定。** 允许 `catch _ => value`、`catch _ { ... }`。拥有的错误值在处理体开始前丢弃；`catch _e` 保留错误值到该处理体离开时。`try`、`catch` 对完整拥有结果执行整体消费，不允许从借用中搬出非 Copy 的成功值或错误值。修复未使用的 `e` 只能改 `_e`，不能自动改成 `_`。
- **V13 自动修复命名。** （2026-11-21：V2 修订后 `v.push(v.len())` 本身合法，不再产生诊断，下述命名规则保留给其他已证明安全的拆分。）固定模式 `v.push(v.len())` 生成 `vLen`；名字冲突使用 `vLen2`、`vLen3`，取当前作用域及补丁覆盖范围内首个不捕获现有绑定的名字。同一文件按源码位置升序产生补丁；下次运行不重复修改。未使用变量按 `_name`、`_name2` 命名。复杂接收者和条件求值不进入自动拆分白名单。候选补丁必须完整、可单独应用并重新通过 check；`let b` 上的 `take` 候选须包含合法化写权限的修改并说明影响。
- **V14 栈溢出（2026-11-21 新增）。** 递归过深或其他原因用尽线程栈时，程序以 panic 类别 P-STACK 终止（退出码同其他 panic），不执行栈展开；运行时尽力写出已缓冲的标准输出。栈溢出时没有可靠的源码位置，记录中的行列为 `0:0`。不运行任何用户 `drop` 的 `Box` 内容（链表、树）按工作列表释放，析构不消耗与嵌套深度成比例的栈；含用户 `Drop`（或接口值）的内容仍按 V10 的顺序递归析构。

## 6. 析构和错误丢弃

`struct T: Drop` 的唯一方法为 `fn drop(inout self)`。用户不能调用该方法，也不能用它返回错误；先本体 drop，后字段自动清理，细则见 V10/V11。Rc/Arc 的 clone 只增加显式共享计数，不深拷贝对象；String/Vec 等的 clone 按对应类型深拷贝。没有自动循环收集，不保证共享环被释放。

`catch _` 丢弃拥有错误后再进入处理体；`catch _e` 保留到体结束。`let _` 明确消费并立即释放整个拥有结果；`let _name` 只抑制未使用警告。修复工具不能把这两种情况混同。

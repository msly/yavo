## 1. 程序骨架和基本语法

入口文件里写 `main`；程序可以只有这一个文件，也可以拆成多个文件（第 6 节）。语句以换行结束，不写分号，代码块必须用花括号。

```
// 导入写在文件开头，例如 use std/fs；没用到的导入会有警告

pub fn add(a: int, b: int) -> int {    // pub：从包导出
    return a + b                         // 必须写 return
}

fn main() {
    let x = 3                            // let：不可变
    var total = 0                        // var：可变
    for i in 0..x {                      // 0, 1, 2
        total += add(i, 1)
    }
    if total > 5 {
        println("big: ${total}")         // 插值直接写到输出，不分配内存
    } else {
        println("small")
    }
}
```

- 循环：`for x in xs { }` 默认只读；`for x in &xs { }` 显式可变，Map 键始终只读。范围循环 `for i in 0..n { }`、`while cond { }`、`loop { }` 配合 `break`、`continue`。
- 分支：`if`/`else` 是语句；要按情况取值，用 `match` 的 `=> 表达式` 分支（必须覆盖所有情况，`_` 兜底）。
- 返回：有返回值的函数每条路径都写 `return`，没有返回值的函数可以自然结束。块体闭包也要写 `return`；单表达式闭包 `(a, b) => a < b` 不用。
- 插值字符串 `"${expr}"` 只能直接传给 `println`、`print`、`eprintln`、`panic`、`assert` 和 `format`。前五个直接写输出，不分配内存；要得到 `String` 用 `format("${x}")`，会分配。`${...}` 里可以写任意表达式，包括函数调用和字符串字面量，如 `"${parts.join(", ")}"`。保留两位小数写 `"${x:.2}"`（只用于浮点数，整数先 `f64(n)`）。
- 字符串转义：`\n`、`\t`、`\\`、`\"`。**每个字符串字面量里的 `${` 都开始插值**：要输出字面的 `${`（如 shell、模板、`"${HOME}"` 这类文本），必须写 `"\${"`，否则报 `E0020`；单独的 `$` 不用转义。
- 注释只有 `//`。声明顺序无关，函数可以先用后定义；`pub` 标记从包导出的函数和类型。
- 入口只能写成 `fn main()`：没有参数、没有返回值（否则 `E0016`）。所以 `main` 里不能用 `try`；可能失败的步骤放进返回 `T ! E` 的辅助函数，在 `main` 里用 `catch` 处理后 `os.exit(1)`，写法见第 5 节。
- 整数溢出、除零、越界移位、超出范围的转换执行时 panic，包括常量可知的表达式。`let b: u8 = 256` 则是字面量类型错误。回绕写 `+%`、`-%`、`*%`；截断转换写 `i32.wrap(x)`，仅接受整数。整数边界写 `i64.min`、`i64.max`。
- 集合字面量 `[1, 2, 3]`、`[:]` 会分配内存；除此之外，普通语法不分配。

## 7. 数值、字符串与内存

| 情况 | 行为 |
| --- | --- |
| 加、减、乘、取负溢出 | panic；生成的 C 用 `__builtin_*_overflow` 检查 |
| 除以 0、对 0 取余 | panic |
| 最小整数除以 -1，或对 -1 取余 | panic |
| 移位量为负，或不小于位宽 | panic |
| 有效移位的结果 | 左移丢弃高位；无符号右移补零，有符号右移补符号位；不依赖 C 编译器的默认行为 |
| 窄化转换超出范围，如 `i32(x)` | panic |
| 负数转无符号 | panic |
| 截断转换 `T.wrap(x)` | 只接受整数；对目标位宽 N，先算数学上的 x mod 2^N，无符号目标直接取这个值，有符号目标按 N 位补码解释。例如 `i8.wrap(130)` 是 -126，`u8.wrap(-1)` 是 255 |
| 浮点转整数 | 向零截断；NaN、无穷或超出范围时 panic |
| 浮点运算和比较 | 按 IEEE 754，不 panic；`NaN != NaN`。浮点数不满足 `Eq`、`Ord`，见第 8 节 |
| `+%`、`-%`、`*%` | 按位宽回绕 |

`-fwrapv` 只是有符号加、减、乘的回绕兜底，不实现上面的 panic，也不覆盖除法、移位和转换；每种运算都有独立的生成规则和边界测试。

- **N1 常量可知的失败。** 普通表达式的溢出、除零、非法移位、越界和失败转换仍按执行时 panic 定义；即使编译器能预先算出，也不能仅因此把有效程序变成编译错误。优化可生成无条件 panic，但必须保留原来的执行路径、先前副作用和 panic 类别。未执行的分支不 panic。默认不产生会被 CI 升级的警告。
- **N2 字面量类型错误。** 无法表示为目标类型的原始字面量（如 `let b: u8 = 256`）是编译错误 E0003；`u8(256)` 是合法的运行时转换表达式，执行时 P-CONVERT。未标注整数/浮点字面量默认 `int`/`f64`，上下文可直接确定字面量类型，这不是已有运行时值的隐式转换。整数 `min/max` 为类型固有常量；`int` 是 `i64` 的别名，`byte` 是 `u8` 的别名。

- **S1** `String` 和 `str` 始终是合法的 UTF-8。
- **S2** `s.len()` 和 `s[i]` 按字节计算，`s[i]` 返回 `byte`。
- **S3** `s[a..b]` 的两端必须落在字符边界上，否则 panic。
- **S4** 任意字节先放进 `Vec[byte]`，再用 `String.fromUtf8(bytes)` 验证，得到 `String ! Utf8Error`；没有 `pushByte`。
- **S5 系统输入。** 文件和标准输入的文本读取遇到非法 UTF-8 时返回编码错误。命令行参数在启动时转换，无法表示为合法 UTF-8 时打印诊断并以非零状态退出。两者都不做静默替换。v1 没有原生路径类型，暂不覆盖所有系统路径。
- **M1 内存耗尽** 时终止进程，和 panic 一样不展开栈。
- **M2 容量计算溢出**（元素个数乘以元素大小等）时 panic，不会分配出过小的缓冲区。
- **M3 分配契约。** 标准库每个操作标注“不分配”或“可能分配”。`yavo allocations` 对一个函数给出三种结果：已知不分配、可能分配、未知（接口调用、C 函数、未知闭包）。参数求值单独计算：`println("${makeString()}")` 里 `println` 不分配，但 `makeString()` 可能分配。
- **M4 集合字面量。** `[1, 2, 3]`、`[:]` 是显式的分配构造；除此之外，普通语法不引入堆分配。
- **M5 `os.args()`** 在进程启动时转换一次（Windows 上这一步会分配），失败按 S5 处理；之后返回 `[]str of static`，调用本身不分配。

## 8. 隐式操作白名单与比较协议

v1 只有下面这些自动操作，其余一律要显式写出；这和“没有隐式转换”并不矛盾，因为白名单是封闭的。

| 自动操作 | 例子 |
| --- | --- |
| 在返回 `T ! E` 的函数里返回 `T`，自动包装为成功值 | `return n` |
| `T` 用在需要 `?T` 的地方，自动包装为有值 | `t = Box(Node{key: k})`、`return best` |
| 需要可复制的 `T`、实际是 `&T` 或 `&inout T` 时，读取一份（复制被借的值，不是复制引用） | `items.push((k.clone(), n))` |
| 方法调用时自动借用接收者 | `v.len()`、`s.trim()` |
| 拥有值传给默认只读参数时借用；内建视图形参允许 `String → str`、`Vec[T] → []T` | `read(text)`、`sum(values)`；不克隆、不取得所有权，不允许 `[]S → []T` 元素转换 |
| 带已有访问许可的内建字段、方法、下标投影 | `p.field`、`box.method()`；不能升级只读权限，不调用用户 Deref |
| 数值字面量由期望类型定型 | `let n: u8 = 3`；已存在的 `int` 转 `u8` 仍须显式转换 |
| 装箱的具体类型用在需要接口的地方 | `Box(Dog{})` 当作 `Box[Named]` |

- **K1 内建比较协议。** `Eq` 是等价关系，`Ord` 是全序。整数、`bool`、`byte`、`str`、`String`（按字节比较），以及元素都满足的元组自动实现。`String` 与 `str` 之间可以直接用 `==`、`!=`、`<` 等比较（按文本字节比较；2026-11-21 决定），这只适用于比较运算符，不使两者成为同一类型，也不改变泛型约束或 `Map` 键类型。浮点数的 `==`、`<` 等是内建的 IEEE 754 运算，但浮点数不满足 `Eq`、`Ord`：泛型约束 `T: Ord` 不接受 `f64`，排序用 `a.totalCmp(b)`，v1 不支持浮点数做 `Map`、`Set` 的键。
- **K2 用户类型的比较。** 显式声明 `struct Version: Ord` 并实现 `fn cmp(self, other: &Version) -> Ordering`。`Ordering` 为内建枚举 `.Less`、`.Equal`、`.Greater`，自身满足 Eq/Ord。`Ord` 蕴含 Eq，相等由 `cmp == .Equal` 定义；只声明 Eq 时实现 `fn eq(self, other: &Self) -> bool`。不允许另一个相互矛盾的 eq 覆盖 Ord 的定义。v1 的用户 Ord 不自动授予 Map 键的哈希能力；标准库当前仅接受已内建定义哈希的键（见库契约）。这不是一般运算符重载。
- **K3 比较函数写错不破坏内存安全。** 用户的 `cmp`，或传给 `sortBy` 的比较闭包违反约定时，结果可能错误，或被检查出来后 panic；标准库的排序和容器不会因此越界或产生未定义行为。
- **K4** 闭包捕获的规则见 O5。

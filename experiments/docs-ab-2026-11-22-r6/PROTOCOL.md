# 第六轮：完整速查卡与精简入口文档的受控对照

## 1. 问题与样本单位

本轮只比较 Yavo 的两种文档入口：完整速查卡，或精简编写说明。语言、编译器、任务、工具接口、可按需查询的 API 文档和模型配置相同。没有 Rust 组；因此本轮即使顺利完成，也不验收“相对 Rust 的单位成功交付成本降低 20%”。

计划 8 个新规格、每臂 2 个独立会话，共 4 个会话和 32 份任务交付。每个会话按 T01→T08 完成全部任务并共享上下文；独立分配单位是会话。该设计测量八题连续任务中的启动文档与按需检索成本，不测量每题独立冷启动。

启动前固定的主要指标：首编且满足全部行为/结构要求的整题数、全部请求实际输入/输出 token、包含失败交付消耗的每份成功交付 token。次要指标：受控操作数、文档实际返回字节、端到端时间、编译进程时间、可见失败与修复次数。两个会话/臂不足以宣布稳定的总体优势。

## 2. 启动硬门槛

在首位受试者获取题目之前，控制器必须保存可独立复核的计量资格回执。资格探针只允许执行 `lab.pl probe doc meter-probe 1`：读取已冻结的中性 `METER_PROBE.txt`，不初始化受试状态，不提供题目或语言文档。至少两次真实 Responses 请求构成“模型调用 → 这一次工具结果 → 模型继续”的完整链，两个请求都必须提供实际 usage。回放合成 JSON 不算资格通过。该链须证明：

1. 每个请求的唯一标识、原始请求与响应、服务实际返回的精确模型标识，以及冻结的请求配置。仅记录请求方填写的可漂移模型别名不足以证明服务模型身份。
2. 每个实际请求的 input/output token usage，缓存输入和推理输出等细分项按原始含义保留；子集不能重复累加。缺失不能变成 0，不能按文本字节估算。
3. 完整工具调用与工具结果链：调用标识、参数、返回内容、失败/重试/取消、请求顺序；记录器日志与服务转录可以逐次对齐。
4. 明确的计时边界、原始服务 usage 的保存位置和哈希；失败请求若计费情况未知，必须保留未知，不能偷偷删除其成本。
5. 文档、题包、编译器、执行器和协议的冻结身份全部通过，真实工具探针未绕过本轮允许接口。

任一项无法满足，状态为 `prepared_blocked`，受试会话数和交付数都保持 0。可以完成题包、文档、记录器、合成契约测试和 CI，但不能以缺失 usage 的探索性运行替代第六轮，也不能把模拟用量写成真实结果。阻塞原因和实际探针单独归档；解除门槛后再记录实际启动时间。

## 3. 两个处理臂与分页

| 臂 | 初始必读 guide | 共同必读与可选内容 |
| --- | --- | --- |
| full | 冻结的完整速查卡 | 相同 API 索引、相同按需 API 主题、相同题目与执行说明 |
| compact | 冻结的精简编写说明 | 与 full 完全相同 |

参与者使用 `doc guide PAGE` 获取本臂的 guide；不能读取另一臂 guide。`doc index PAGE` 和 `doc api.TOPIC PAGE` 对两个臂返回同一份冻结内容。索引指向主题接口，不能诱导直接读取仓库、实现或另一臂文档。

所有文档共用 **每页最多 8192 个 UTF-8 字节**的确定性分页规则；不切断 UTF-8 字符。记录页号、总页数、原始字节偏移、返回字节数和源文档/返回内容哈希。一次请求只返回一页，不能通过不同包装合并操作或省略大段内容。全部 guide 页和共同 index 页必须在第一次 build 之前成功读取；记录器强制检查，不能仅依赖最终自报。任务说明和按需主题可以随任务读取。

分别累计 mandatory_initial_guide、mandatory_index、task_documentation、on_demand_api、repeated_read 的实际字节和操作。精简组为解决缺失信息进行的后续查询保留为该处理的实际成本；不能只比较首次输入，删去检索、编译修复或失败题成本。预先必读 guide 的不同页数本身属于交付策略处理；并非“每臂强制同样的读卡操作数”。

## 4. 会话安排与隔离

| 波次 | 启动顺序 | 会话 | 处理 | 题序 |
| --- | ---: | --- | --- | --- |
| 1 | 1 | full-a | 完整 guide | T01→T08 |
| 1 | 2 | compact-a | 精简 guide | T01→T08 |
| 2 | 1 | compact-b | 精简 guide | T01→T08 |
| 2 | 2 | full-b | 完整 guide | T01→T08 |

每波两个会话并发；第二波交换处理启动次序。每个会话从独立空白上下文启动，使用同一精确服务模型和冻结请求配置。服务若支持 seed，预先记录取值与使用方式；不支持的参数标为不支持，不声称随机性已被完全控制。任何实际模型身份漂移使该批失去比较资格，不换名字后继续计入原批。

不继承父会话的任务讨论、参考实现、隐藏结果、其他受试源码或旧轮答案。每个参与者只能使用自己的源文件目录和指定 lab 接口。禁止网络查找、其他编译器、外部依赖、委派，以及自行修改语言、运行器或题目。提示约束和允许接口不等于操作系统级强隔离；转录必须审计实际偏离。

源代码第一次调用编译器前的完整源图是首稿；保存每次写入和每次构建前快照，不用后续修复替换首稿。每题最多 8 次实际编译调用，失败与未完成按原样保留。成功构建后至少运行一次公开用例再提交。交卷不可撤销，全部四个会话封卷后才允许执行隐藏裁判。

build 请求在进入编译器前被接口拒绝，仍计一次失败请求，但不产生首稿快照、不占实际编译编号。汇总分列首次 build 请求成功与首次实际源码回放成功，接口失败消耗保留在成本中。

## 5. 题目、裁判与结构要求

题包含 16 个公开输入、96 个隐藏输入，每题 2 个公开、8 个命名边界和 4 个固定种子随机输入。每题通过要求全部对应输入在 stdout、stderr、退出状态上逐字节匹配；T04/T06 还必须通过源码哈希绑定的结构审查。

- T04：至少两份源码；字段解析、日期校验和全部日期运算在非入口模块。主文件仅做 I/O 与模块调用。
- T06：两个 OS 工作线程均在首次 join 前启动，空分片也启动；各自分解规定的偶/奇索引输入，主线程不能重新分解或把全部工作放在一条线程中。

首稿和终稿分别重放；计划的 32 份交付会产生最多 64 个源码阶段和 896 次程序执行，其中公开 128、隐藏 768。它们是重复验证量，不是 896 道独立题目。未提交或编译失败的阶段保留实际缺失/失败，不能为了凑够计数伪造执行记录。

参考实现只读规格与输入，不读受试解答。`judge/generate.py` 包含手算锚点及替代算法验证：环形淘汰对数学递推、多项式对数值恒等式、日历对独立序数公式、有界找零对穷举、矩形压缩对单位格、棋盘合法性穷举全部 3^9 状态、递归 minimax 对自底向上图求值。全部输入检查公开的长度/数值上限。

T07 最多 60 个矩形、坐标 ±1000，坐标压缩后的网格最多 119×119。T08 每个输入最多 20 行、棋盘最多九格；合法可达状态只有有限的 3^9 候选域。程序超时和输出限制由冻结运行器执行并保留真实故障类别，不在看到结果后调整。

## 6. 冻结清单

先生成准备清单，绑定题包 20 份文件及 packet-manifest、PROTOCOL/PARTICIPANT、两种 guide、共同索引和全部 API 主题、中性计量探针、lab 与裁判/汇总程序、四会话分配和任务顺序。只有确定真实请求的模型配置后，才创建运行冻结清单，把这些准备材料、模型请求模板/配置、编译器/运行时/后端工具身份、环境覆盖与资源限制一起绑定。

绑定顺序为“准备材料 → 运行与模型冻结 → 引用该冻结的真实计量资格回执 → 同时引用冻结与资格回执的启动记录”。运行冻结不能包含引用自身的资格回执哈希，任何清单也不能包含自身哈希。题包清单由生成器创建；控制器清单记录其他身份和实际冻结时间。先提交运行冻结材料、验证真实资格并保存启动记录，再允许受试启动。模型配置或计量未就绪时，只保留准备清单和零会话状态。冻结后任何需要修改的输入必须生成新批次/新清单，不能保留原试验身份覆盖文件。报告、观测转录和复核记录可在执行后新增；原始记录保持不变。

## 7. 成本解释与最终判定

按请求原样保存真实 usage，汇总所有实际消耗，包括失败和修复；同时列每个会话与每个任务。API 价格若未冻结可核验的时间/型号/费率，只报告 token，不编造美元费用。单题成本在共享上下文中包含历史内容，不能把请求 input token 全部归为当前任务新输入。

时间分为会话 init→seal、受控操作体、编译进程和执行进程；残差包含模型生成、网络/工具往返、排队和调度，不能直接标为“推理时间”。操作数与平台服务请求数分列。缓存 usage、文档返回字节与模型 token 也分别报告。

本轮比较结论只针对预先固定的文档策略与此题包。四个会话不足以建立稳定总体效应；失败来源需按文档遗漏、语言误用、算法/题意、环境和协议偏离分开。没有受试启动时，只能报告准备完成和门槛状态，不给正确率、成本比或成功样本。

八份规格没有复用旧轮题包或答案。矩形并集使用的区间/网格技巧与早期任务存在抽象算法关联，线程/模块结构也服务于同一语言能力；不称为严格的全部题型留出。后续 60 题 pilot 和不少于 400 题的正式跨语言评测仍需独立方案。

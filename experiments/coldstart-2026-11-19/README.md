# 冷启动实验（2026-11-19，编译器 `e7e106f`）

规划“主要风险”一节的第一项：只给 agent 速查卡，看它能否写出能通过检查、结果正确的程序。

## 做法

- 题目：`TASKS.md` 里 10 道 26–82 行的命令行小题（词频、成绩汇总、查找行、逆波兰计算器、`?Box` 二叉树、
  `Map` 库存、折行、接口、泛型栈括号匹配、生命游戏），覆盖标准输入、命令行参数、文件、退出码、枚举和结果类型、
  `Box`、`Map`、浮点、接口、泛型结构体、切片。输入在 `tasks/`，期望输出由 `tasks/ref.pl`（Perl 参考实现）生成。
- 受试者：一个新开的 agent（与本会话同一模型），工作目录里只有速查卡（`docs/cheatsheet.md` 的副本）、
  `TASKS.md`、`tasks/` 和编译器二进制；明确禁止读仓库、编译器源码、测试和规范其他文件。
- 记录：每次 `yavo build` 记一行（`programs/LOG.md`）；通过 = 编译成功且标准输出逐字节相同（T02 另比标准错误，
  T03 另查两种退出码）。结果由我在 agent 之外重新编译、运行、`diff` 复核，并用 `YAVO_ALLOC_CHECK=1` 查堆块。

## 速查卡的缺口（agent 报告，均已用编译器验证）

agent 没有因此编译失败，但这些地方要靠猜或保守绕开：

1. 没有泛型结构体的例子（只有泛型函数）；agent 猜出 `struct Stack[T]`、`Stack[int]{items: []}` 和
   `fn push(inout self, x: sink T)`，都对。
2. 没写 `main` 只能是 `fn main()`；因此 `try` 不能在 `main` 里用。agent 一开始就改用“辅助函数返回 `int ! io.Error`，
   `main` 里 `catch e { eprintln(...); os.exit(1) }`”。值得写成标准模式。
3. 没写 `"${b}"` 对 `byte` 打印数字（`97`），而不是字符。agent 猜到并用 `s[i..i+1]` 打印单个字符；否则 T09 会输出错误。
4. `v.join(sep)` 只接受 `str`/`String` 元素，速查卡没注明。
5. `?T` 的方法（`isSome`/`isNone`）只在例子里出现；`if let ... else` 没有示例。
6. `Map` 哪些方法接受 `str` 键（`get`、`getCopy`、`has`、`remove` 都接受）、`String.push` 接受什么，没有写清。

## 解读和局限

- 受试者是与开发者同一模型；题目由开发者在实现完功能之后设计，`TASKS.md` 还点名了要用的特性
  （`?Box`、接口、泛型 `Stack[T]`、`totalCmp`），这会抬高通过率。它说明速查卡对“会用 Rust/Go 的 agent”
  基本够用，不等于对任意任务够用。
- 题目偏小（单文件、单线程、无第三方库），没有测并发（P3 尚未实现）和 `yavo fix`。
- 没有测 token 消耗，也没有与 Rust 并行做同一组题。下一轮可以：换一组不点名特性的题、让另一模型做、
  同时用 Rust 做对照。

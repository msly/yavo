## 交卷后边界抽查：T10 前导零

T10 要求数值在 1 到 10^7 之间的十进制整数，未禁止前导零。输入 000000001 表示整数 1，其 Collatz 变换次数为 0、峰值为 1。Yavo 源码 parseN 额外限制字符串长度不超过 8，错误拒绝该输入。

| 结果 | Yavo | Rust |
| --- | --- | --- |
| stdout 第 1 行 | line 1: invalid | 1: steps=0 peak=1 |
| stdout 第 2 行 | longest: none | longest: 1 (0 steps) |
| stderr / 退出码 | 空 / 0 | 空 / 0 |
| 边界判断 | 失败 | 通过 |

该检查使用冻结的 1af1f69 编译器和未修改的受试源码重新构建；Yavo 仍启用堆块检查。输入、预期、实际输出和退出码保存在 evidence/t10-leading-zero.*；[复现脚本](evidence/run-t10-leading-zero.sh) 会校验 Yavo 编译器哈希。

这是交卷后按代码审计发现的一个定向样例，不并入原 18 用例分母、不修改原首编日志，也不能据此估计整体错误率。它证明现有题包遗漏了一个合法输入，后续新题应加入独立隐藏边界用例。

## 本轮能支持的决定

1. 同题包上的首编和迭代次数有所改善，Yavo 仍低于 Rust；“agent 写 Yavo 比写 Rust 高效”尚无支持证据。
2. 下一轮同时保存逐次编译命令、退出状态、首次源码、token 分类、工具调用与单调时钟计时。把编译失败、编译后逻辑失败、环境错误、修复题分开记录。
3. 消除本轮具体障碍后，用同难度的新题并增加隐藏用例；每种语言采用多个独立运行，避免把一次顺利或不顺利的执行当作语言总体表现。

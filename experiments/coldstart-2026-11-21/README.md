# 第三轮冷启动实验（2026-11-21，编译器 `a9fbefc` + 速查卡 `7cc377c`）

目的：第二轮之后加了并发、Arena/Id、多文件模块、`yavo fix`，但“agent 写 Yavo 比写 Rust 高效”这一指标一直没再测。本轮用新题覆盖这些功能。

## 做法

- **开跑前先修速查卡**（`642e8be`、`7cc377c`）：删掉“编译器还不存在”、6 个不存在的命令、`test` 块、`std/time/rand`；补多文件模块、Arena 方法、Deque、`\$` 转义、`ch.close()`；新增第 9 节“尚未实现”。受试者拿到的是 `cheatsheet-used.md`（与 `7cc377c` 逐字节相同）。
- **题目**：`TASKS.md` 12 道新题，不点名语言特性：好友图（含删除与重新加入）、带撤销的文本缓冲区、表达式树、配置文件解析（多文件，≥2 文件）、课程规划（多文件，≥3 文件）、4 线程分段统计、作业调度、修复题、可移动子树的文件系统、3 线程动态分发、LCS 行差异、哈夫曼编码。
  期望输出由 `ref/ref.py`（Python，受试者看不到）生成。T08 修复题两种语言各有一个埋了同样 5 类错误的程序（`ref/T08/` 是正确版本，两者输出一致）：移动后使用、借用期间修改、返回借用缺来源/生命周期、从元素移出、遍历 Map 时修改。
- **受试者**：Claude Sonnet，两个独立 agent 同时运行，提示词除语言部分外相同。各自只有沙盒目录（Yavo 组：速查卡、`TASKS.md`、`tasks/`、`bin/yavo`；Rust 组：`TASKS.md`、`tasks/`、`bin/rustc`）。每次调用编译器记一行日志，每题最多 8 次。
- **复核**：`verify.sh` 在 agent 之外重新编译并比对标准输出、标准错误和退出码，并检查代码结构要求（文件数、确实创建线程）。Yavo 用 `YAVO_ALLOC_CHECK=1` 构建。

## Yavo 组 8 次有效失败的分类

| 类别 | 次数 | 题 | 具体 |
| --- | --- | --- | --- |
| 实现缺口，速查卡写错或漏写 | 2 | T03、T05 | 结构体字段默认值 `y: f64 = 0.0`（速查卡示例就这么写）→ `U0001`；下标赋值 `v[i] = x` → `U0001`（速查卡没提，agent 改用 `Map[int, V]` 当数组） |
| 刻意的设计，与常见语言直觉相反 | 4 | T11、T12、T09、T01 | 不做两阶段借用：`tab.push(f(tab))`、`cnt.push(cnt[x] + cnt[y])` → `E0403`（2 题；Rust 接受后者）；`String == str` → `E0001`（**连续两轮都踩**）；非 Copy 值用 `getCopy` → `E0404` |
| 速查卡写了但没看到 | 2 | T04、T02 | 字符串里的 `"${"` 要写 `"\${"` → `E0020`；对已有可选变量 `if let` 只借用，要 `match take(&o)` → `E0404` |

**没有出现的失败**：图（T01，删除后再加入）、子树移动（T09）、哈夫曼树（T12）、表达式树（T03）都没有所有权/借用相关的编译失败；两道并发题（T06 分段、T10 channel 动态分发）都是第一次编译通过；多文件两题唯一的失败是 `${` 转义，与模块无关。

受试者从未使用 `yavo fix` 或 `yavo check --json`。实测 `yavo fix` 也不会自动拆开 `c.push(c[0] + c[1])`。

## 解读

- 最终正确性两边相同，且 Yavo 程序全部通过堆块检查。差距仍在**一次写对的比例**（3/11 对 11/11，比第二轮的 7/10 对 9/10 更大）和**成本**（token 多 32%，工具调用 2.4 倍，与第二轮的 29% / 3 倍基本一致）。题目更难、用到更多新功能后，差距没有缩小。
- 8 次失败里没有一次是“所有权模型本身太难”：2 次是实现缺口（且速查卡误导），4 次是几条与 Rust/常见语言直觉相反的规则，2 次是文档写了但放在不显眼的位置。这三类都可以靠实现或语言决定消掉，而不是靠更长的文档。
- 唯一 Yavo 明显占优的地方是 T08：一次报出全部错误，修复题能一轮完成；rustc 分阶段报错，agent 要么多编译一轮，要么在没有编译器确认的情况下改代码。

## 实验后的修改

速查卡已按本轮发现补正（`cheatsheet-after.md`）：字段默认值、下标赋值列入“尚未实现”并给替代写法；规则 7 明确“实参里任何读接收者的表达式都会被拒绝”；第 3 节说明对临时值与已有变量 `if let` 的区别；`Map` 行补非 Copy 值的取法。编译器未改。

## 局限

- 每组仍只有一个受试者、一次运行；题目由开发者设计；Rust 组的模型有大量 Rust 先验，这正是对照要测的差距，但不能把差距全部归因于语言设计。
- 沙盒隔离靠提示词约束：mcp-3 能访问整个工作区，无法强制禁止受试者读仓库。两份报告都声明只在沙盒内读文件（Yavo 组有一次往 `/tmp` 写临时输出）。
- 结构要求只检查文件数和是否出现线程创建，不检查分段或动态分发是否真按题意实现（两组代码人工抽查：Rust 用原子计数器、Yavo 用 channel 实现动态分发）。

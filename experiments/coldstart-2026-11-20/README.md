# 第二轮冷启动实验（2026-11-20，编译器 `0ed6802`）

上一轮（`../coldstart-2026-11-19/`）的三个局限：题目点名了要用的特性、受试者与开发者是同一模型、没有对照。这一轮分别改掉。

## 做法

- **题目**：`TASKS.md` 里 10 道新题（列统计、日志汇总、账户、矩阵乘法、依赖排序、游程编码、罗马数字、图形面积、目录大小树、LRU 缓存）。
  只描述输入和输出，**不点名任何语言特性**；包含错误路径、退出码、标准错误、浮点两位小数和刻意设置的检查顺序。期望输出由 `ref/ref.pl`（Perl）生成，
  受试者看不到参考实现。T01 原本有一个恰好落在 x.xx5 上的平均值，各语言的舍入可能不同，已改掉。
- **受试者**：Claude Sonnet（与编写编译器的模型不同），两个独立的新 agent 同时开跑，提示词除语言部分外相同：
  - Yavo 组：只有速查卡（`docs/cheatsheet.md` 副本）、`TASKS.md`、`tasks/` 和 `yavo` 二进制；禁止读其他任何文件、禁止上网。
  - Rust 组：只有 `TASKS.md`、`tasks/` 和 `rustc`（edition 2021，只用标准库）；同样的限制。
- **记录**：每次编译一行（`yavo/LOG.md`、`rust/LOG.md`），每题最多 8 次编译。token 和用时取自 agent 运行记录。
- **复核**：由我在 agent 之外用 `verify.sh` 重新编译全部程序并比对标准输出、标准错误和退出码；Yavo 程序用 `YAVO_ALLOC_CHECK=1` 构建，全部退出码为 0（无泄漏、无重复释放）。

编译失败的原因：

| 组 | 题 | 原因 |
| --- | --- | --- |
| Yavo | T01 | 速查卡列出的 `Set[T]` 和 `"${x:.2}"` 编译器都报 `U0001`（未实现）；agent 改用 `Map` 计数并手写两位小数格式化 |
| Yavo | T05 | `${...}` 里写了字符串字面量（`${parts.join(" ")}`），`E0020`；速查卡没写这条限制 |

两组都没有出现借用或所有权相关的编译错误。

## 解读

- 不点名特性、换了模型以后，只看速查卡的 Yavo 仍然 10/10 通过、零错误输出；差距在第一次编译成功率（7/10 对 9/10）和 token（多约 29%）。
  多出的 token 一部分是读 28 KB 的速查卡，一部分是绕开 `Set`、`:.2` 的手写代码（行数差主要来自这里和 Rust 组更紧凑的写法，行数不宜直接比较）。
- 三次有效失败都不是语言规则难，而是**速查卡和编译器不一致**（2 处）或**没写的限制**（1 处）。这是可以直接修的问题：
  1. 实现 `${x:.2}` 和 `Set[T]`（规范里都有，速查卡已经在教）。
  2. 速查卡补：`${...}` 里不能写字符串字面量；`String` 与 `str` 不能直接比较（写 `s == t.toString()` 或比较两个 `str`）；
     `os.args()` 的第 0 个是程序名；没有 `Vec.remove`/`insert`、`Map.keys`（截至本轮）。
- agent 猜对了很多速查卡没写的东西（`split` 保留空字段、`[]str` 也能 `join`、闭包可捕获 `int`、`main` 可以 `return` 等），说明写法与常见语言接近。

## 局限

- 仍然是一个受试者、一次运行，没有重复；Rust 组的模型对 Rust 有大量先验，这正是对照要测的差距，但不能把差距全部归因于语言设计。
- 题目由开发者设计；Rust 对照不检查内存安全以外的性质，Yavo 的堆块检查发现不了释放后使用。
- 没有测并发（P3 尚未实现）和 `yavo fix`。

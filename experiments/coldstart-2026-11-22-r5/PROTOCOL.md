# 第五轮新题实验协议（2026-11-22）

## 1. 本轮回答的问题

在第四轮之后的编译器与速查卡上，比较 Yavo、Rust 完成 **12 道新题**的首次编译、公开样例、隐藏边界正确性，以及受控工具操作数和端到端耗时。每语言运行两个独立批次，共 48 份任务交付；任务间共享同一批次会话，独立单位是四个批次，不是 48 个独立会话。

**本轮不具备完整 token 成本验收条件。** 当前协作接口未向编排者提供可核验的 usage、精确服务模型 ID 或采样参数，全部保留 `null`。先完成有证据支持的正确性与受控操作诊断；正式“单位成功交付成本比 Rust 低 20%”门保持 `blocked`。执行器探针见 [executor-probe.json](evidence/executor-probe.json)。

## 2. 冻结与隔离

- 语言实现基准为 `5cd916bbe7c8a85776b14e2295a681db88fb5c0a`，其中最后代码改动为 `8a65228f31139a4b07e256fec70ccd6aaff06176`。实验文件的后续提交不改变该语言基准。
- 首个受试批次开始前，冻结 TASKS、公开输入/预期、隐藏输入/预期、独立参考实现、Yavo 速查卡、编译器、Rust 工具链和运行器。以机器生成的 SHA-256 清单为准，不能仅依赖文件名或日期。
- 四批收到相同任务、相同公开样例和相同任务顺序。仅语言、对应工具和 Yavo 速查卡不同；不提供旧轮答案、其他受试源码、隐藏用例或参考实现。
- 使用 `collaboration.spawn_agent(fork_turns="none")` 启动各批次，不继承父会话题目分析、判定材料、旧失败和其他批次结果。不指定模型或推理强度覆盖，继承父级相同配置；精确模型 ID、采样与可核验 token 计量仍未知。
- 每批使用独立目录和源文件；不得读其他批次或仓库实现。所有受试文件操作与程序执行必须经过服务器 `tools/lab.pl` 的允许操作。该约束由提示词和请求日志审计，不宣称是平台层强制隔离。
- 隐藏判定在所有交付冻结后进行，不把隐藏失败反馈给受试者修改。交卷后的修补、诊断和编译器修改单独归档，不覆盖原交付或重新定义本轮成功。

## 3. 四批次安排

| 波次 | 会话启动顺序 | 语言与批次 | 题目顺序 | 运行关系 |
| --- | --- | --- | --- | --- |
| 1 | 第一个 | Yavo A | T01 → T12 | 与 Rust A 并发 |
| 1 | 第二个 | Rust A | T01 → T12 | 与 Yavo A 并发 |
| 2 | 第一个 | Rust B | T01 → T12 | 与 Yavo B 并发 |
| 2 | 第二个 | Yavo B | T01 → T12 | 与 Rust B 并发 |

第二波交换语言启动次序，且必须重新创建两个空白会话。不能把已完成 A 的会话清空目录后当作 B。并发的资源争用和服务排队仍可能影响耗时，换序不消除这些影响。每题最多八次 `build` 请求；接口不开放单独的 `check`，不能用改名或换包装绕过上限。到达上限或不能完成的题保留失败/未完成状态。

## 4. 受控操作与自动记录

受试者每次工具调用只请求 **一个** `lab` 操作；禁止把多个操作、任意 shell 命令或另一路文件访问合并到同一请求。允许的读、写、构建、运行等操作以实际运行器接口为准。编排者的布置、判定和归档操作分别记录，不计入受试成本。

每个受试请求自动保存：

- 批次、语言、任务、连续序号、操作类型，以及操作开始/结束的单调时钟；
- 请求参数、可见输出、退出状态、超时/失败类别；
- 每次源码写入的实际字节和 hash，以及每次编译前的完整源图快照；
- 编译命令、工作目录、工具身份、构建结果和程序执行结果。

“首稿”主判定使用该题**第一次编译器调用之前**的完整源图。首次写入版本也保留，但不与首次编译版本混用。首编失败不能用后续源码重编后改记成功。包装器自身错误、路径错误、超时等仍保留在记录中。

主计量单位是 **受控 lab 操作（lab operations）**：一个受试 `lab` 请求对应一次远程执行调用。外层 `functions.exec` 包装、平台编排、通知与不可见的额外调用不计入；该值不得写成“平台总工具调用”。若发现绕过 `lab` 的操作，记录协议偏离及可见影响，不能按零成本处理。

调用按可复核行为分类：读速查卡/文档、读题目/公开样例、首次写代码、构建、运行、失败后的源码修改；其余允许操作单列。源码修改再按已观察到的编译失败或公开样例失败区分。分类不能仅依赖受试者自报“修复”或“正常编辑”。

## 5. 时间与缺失计量

- 用服务器 `Time::HiRes::clock_gettime(CLOCK_MONOTONIC)` 记录事件边界；UTC 时间仅用于定位，用户日期按 Asia/Shanghai。
- 批次时间以运行器明确记录的开始事件至提交结束事件为准，保存两端原始值和实际边界说明。区间覆盖读题、推理、受试操作执行和等待；开始前的布置、结束后的隐藏判定分别记录，不混入。
- 若记录从首个受试操作才开始，必须按实标注这一边界，不能声称包含调度与首次调用之前的时间。编译/程序执行子耗时和批次端到端耗时分列。
- 所有批次 `tokens=null`、`exact_model_id=null`、`sampling=null`，并附缺失原因。禁止按字数、代码长度、历史比例或主观估计补数。
- 本轮时间用于这四批受试的端到端诊断，不能当作严格的宿主机编译性能或语言运行性能基准。工具等待、模型服务速度、并发和缓存状态影响时间。

## 6. 判定与统计口径

| 指标 | 判定 |
| --- | --- |
| 首次编译命令成功 | 第一次编译器请求及实际命令成功；路径/包装失败也计入实际命令口径 |
| 首稿代码可编译 | 冻结首次编译源图可构建；若与上一项不同，保留两项和具体环境原因 |
| 首稿公开样例正确 | 用首次编译源图在独立复核中比较 stdout、stderr、退出状态 |
| 首稿隐藏正确 | 对同一首次编译源图执行冻结隐藏用例；首编失败不能算通过 |
| 最终公开/隐藏正确 | 用冻结交付源图分别判定；全部约定用例与结构要求满足才算该题通过 |
| 首次与最终构建/运行尝试 | 从请求记录计算，保留所有失败和重试 |
| 受控操作与时间 | 批次总量与每题分项；成功交付的成本口径仍须计入失败题消耗 |
| token成本 | 缺失，门状态 blocked，不计算Yavo/Rust token比值 |

逐例比较标准输出、标准错误和退出状态；结构要求另审计实际源码，不能只凭出现某个线程关键字判定满足。参考实现与隐藏用例由未写受试解答的一方生成和复核，隐藏用例须覆盖空值/边界、重复、顺序、非法输入及题意允许的特殊表示等实际适用类别。

报告列出 A/B 各批次和合并分子/分母；分离编译失败、语义/算法错误、运行时故障、环境错误、协议偏离与未完成。只有两个独立批次/语言，不据此声称稳定总体优势或正式统计验收通过。

## 7. 与旧轮的关系

本轮是 **12 份新规格**，其中三题组合了历史题型与新规则：T01 原子转账账本沿用第二轮的账户题型并增加 batch 原子回滚等规则；T06 将第二轮游程编码改为三线程分段与边界归并；T07 在第二轮 LRU 上加入 TTL 到期机制。它们不复用原题包、原输入或原答案，但不能称为“12 个全新题型”或严格的题型留出评测。新规格和隐藏边界的独立复核见 [preflight-review.json](evidence/preflight-review.json)。

第三、四轮报告称受试者为 Claude Sonnet，但精确模型、采样、转录和首稿未完整存档。本轮使用当前父级配置的空白协作会话，任务也不同。历史数字可作背景，不把跨轮变化归因于三项语言/诊断修改，不把受控 lab 操作与旧轮平台工具调用直接求比。

本轮用于定位首次失败与新增操作的来源，决定下一批实现/速查卡工作。完整 v1、正式 Agent 成本门和正式运行性能门继续按 `docs/plan.md` 独立验收。12题诊断不替代60题pilot与不少于400题的正式设计。
